# User Stories
## OLTP User Stories
| # | Epic | User Story | Acceptance Criteria| Priority |
|---|-------|---------|---------|---------|
| OLTP-1 |User Accounts and Login| As a Senior I want to be able to login so that I can information that pertains to me. | <ul><li> Warning System <ul> <li>Attempts 1-2: error message only</li> <li>Attempt 3: warning</li> <li>Attempt 5: account locked until email reset </li> </ul> <li>Successful login will show the home page</li> <li>Unsuccessful login will show a warning</li></ul>| Major |
| OLTP-2 ||As a Senior I want to be able to easily set up a secure account so that I can keep of my personal information.|<ul><li>Password is encrypted and stored safely</li><li>Form contains boxes for:<ul><li>First Name (R) </li><li>Middle Name (O)</li><li>Last Name (R)</li><li>Email Address (R)</li><li>Phone number (R)</li><li>Address (R) <ul><li>Ensure Street, City, Country, Province, Postal Code are separate boxes</li><li>Add auto-fill eventually?</li></ul></ul><li>Insurance (O)<ul><li>Company</li><li>Account #</li></ul></li> <li>Password and email are stored and encrypted in the database</li><li>Selection option for Patient or Family </li> </ul>| Major |
| OLTP-3 ||As a Senior I want my sessions to be secure so that I can have safe of mind that my data is protected.|<ul><li>Cookie sessions implemented</li><li>Session expires after 30 minutes of inactivity</li><li>Logout and Login are secured</li><li>Patient pages should not be accessible without the correct accounts</li>| Minor |
| OLTP-4 |User Roles and Permissions | As the admin, I want to be able to turn employee accounts into admins through a button locked by a passkey so that I can easily let them work and be secure.|<ul><li>Button to turn account into admin pops up a password</li><li>Successful password will turn account into admin </li><li>Unsuccessful password will do nothing until 3 attempts, which will issue a warning</li><li>5 attempts will log the admin out</li></ul>| Major |
| OLTP-5 ||As an admin, I want a clear hierarchy of roles and permissions so that I can ensure proper access to all users.|<ul><li>All roles are defined</li><li>All permissions are defined for each role</li><li>Permissions following least privilege only philosophy<ul><li>Only give each role what that role requires to work. Otherwise do not give them that permission.</li></ul></li><li>Roles include Senior, Family Member, Caregiver, Admin and Agency Manager</li></ul>| Major |

| OLTP-8 |Update |As a Senior I want to update personal information so that it is up to date.|G = Greyed out/Can’t update </br><ul><li>Full information<ul><li>First Name [G]</li><li>Middle Name [G]</li><li>Last Name [G]</li><li>Email Address</li><li>Phone number</li><li>Address</li><li>SIN number [Last 3 digits shown only] [G]</li><li>Birthday [G] </li><li>Living alone (yes/no)</li><li>Current Doctor</li><li>Emergency Contact</li><li>Power of Attorney</li><li>Current Medication</li></ul></li><li>If user requires any changes due to mistakes when creating/inputting information, requires customer support</li></ul>| Minor |
| OLTP-9 |Delete|As a Family Member I want to be able to deactivate my parent/grandparent’s account if it is no longer needed so that I don’t have to worry about the account any more.| <ul><li>Delete does not delete, archived senior data is retained for 5 years</li><li>Option to permanently archive</li><li>Delete does not happen instantaneously</li><li>Removes user account from active to deactivated.</li></ul>| Minor |
| OLTP-10 |Family and Emergency Contact Assignment|As a family member I want to leave my number so I can be contacted during emergencies.|<ul><li>Emergency contact form can be filled in the profile<ul><li>Contains:<ul><li>First name</li><li>Last name</li><li>Phone number</li><li>work phone number (optional)</li><li>relationship</li></ul></li></ul></li><li>Can have multiple emergency contacts</li><li>If emergency contact has an account, can be assigned as emergency contact as well.</li></ul>| Minor |
| OLTP-11 ||As a family member I want to check on my grandparent/parent health and notes from caretakers and doctors so I can make sure they’re okay and follow any instructions that have been left.|<ul><li>Family member creates separate login</li><li>Family ID is added to the patient’s account to view patient information</li><li>Only able to access assigned patient information</li><li>Same home page as a normal account, just added tab for parent/grandparent information</li><li>Assignment to elder account requires elder account login password</li></ul>| Minor |
| OLTP-12 |Caregiver Assignment|As a caregiver I want to see all the patients I have been assigned so that I can manage my time and make it to each appointment.|<ul><li>List of patients displayed in order of appointment times </li><li>Table format<ul><li>Time</li><li>Patient Name</li><li>Appointment Type</li><li>Resident address</li><li>Destination address (if applicable)</li></ul></li><li>Any notes from previous caretakers on a patient</li></ul>| Major |
| OLTP-13 ||As an admin I want to be able to assign qualifying caretakers to my patients so that I can ensure their needs are met.|<ul><li>List of patients displayed</li><li>Searchable by patient name</li><li>Drop down for eligible caretakers<ul><li>Eligibility:<ul><li>Trained</li><li>Time availability</li></ul></li><li>May cull caretakers list in the backend and only display eligible caretakers in the frontend</li><li>Each caretaker shows the agency they belong to</li></ul></li><li>Separate list for patients who do not have assigned caregivers for admin to work through.</li></ul>| Major |
| OLTP-14 |Visit Logging and History|As a caregiver I want to be able to check-in and out when I reach my patient’s location and after I’m done so that my boss knows when I started and finished.|<ul><li>In list of patients (Caregiver Assignment) user is able to select the patient in question to enter another page where they can log their activity</li><li>Check in button, check-out button</li><li>Logs the time of arrival and time of checkout and this is registered in the database as well</li><li>Visit record stores ScheduledStart, ActualCheckIn, ActualCheckOut and Status</li></ul>| Major |
| OLTP-15 ||As a caregiver I want to be able to leave notes under my patients account so that future caretakers know what to expect or what to do better.|<ul><li>In list of patients (Caregiver Assignment) user is able to select the patient in question to enter another page where they can log their activity</li><li>Expandable text box that is available in the same window as the check-in/check-out</li><li>Use a button to save</li><li>Caretakers cannot erase previous caretaker notes</li><li>Only most recent (within 7 days) will show.</li><li>Can archive older notes</li><li>(If there is a potential for AI, it would be good to use it here to monitor for abusive language or detrimental notes on the patient to prevent patient abuse)</li></ul>| Minor |
| OLTP-16 (Added) |Visit Scheduling|As an admin I want to schedule a visit for a senior with a caregiver so that the visit appears on the caregiver's list and can be tracked.|<ul><li>Admin selects senior, caregiver, date/time and visit type (doctor, home visit, bathing, etc)</li><li>Saved visit has ScheduledStart set and Status = Scheduled</li><li>Scheduled visit appears in the caregiver's assigned list (OLTP-12)</li></ul>| Major |
| OLTP-17 (Added) |Missed Visit Detection|As an Agency Manager I want missed visits to be marked automatically so that reliability reports are accurate without manual entry.|<ul><li>Visit with no check-in within 60 minutes of ScheduledStart is set to Status = Missed</li><li>Cancelled visits are never marked Missed</li><li>Marking runs automatically (scheduled job or trigger), no manual step</li></ul>| Major |
| OLTP-18 (Added) |Agency and Agency Manager|As an admin I want caregivers linked to an agency, and an Agency Manager role, so that managers can see and manage their own agency's caregivers and visits.|<ul><li>Each caregiver belongs to exactly one agency</li><li>Agency Manager can view only caregivers and visits of their own agency</li><li>Admin can assign or change a caregiver's agency</li></ul>| Major |

## OLAP User Stories
| # | User Story | Acceptance Criteria| Priority |
|---|-----------|--------------------|---------|
| OLAP-1 |As an Agency Manager I want to be able to see the trend of scheduled visits and success or failure rates so I can accurately check on the reliability of services.|<ul><li>Line chart</li><li>Data is formatted with Date/Time as the x-axis and number of visits as the y-axis taking into account all accounts</li><li>2 lines, one is success and one is failure</li><li>separated by types of visits (doctor, home visit, bathing, etc)</li><li>Failure = Missed visit; Missed % = MissedCount / scheduled VisitCount, cancelled excluded (Query 1)</li></ul>| Major |
| OLAP-2 |As an Agency Manager I want to be able to check caregiver late clock ins so that I can fix the issue and ensure our patients are getting the care they need.|<ul><li>Bar chart</li><li>x axis are names, y axis is time/minutes of difference between scheduled times</li><li>A visit is late if check-in is more than 10 minutes after scheduled start; bars show average minutes late per caregiver</li><li>Can be grouped by agency and time of day (Query 3)</li></ul>| Major |
| OLAP-3 |As an Agency Manager I want to know how many seniors are missing appointments so that I can assign a status update on them and ensure they are getting the appropriate help required.|<ul><li>Table</li><li>Name, Appointments missed, appointment types [as a list in a single column]</li><li>Flag seniors with 3 or more missed visits in the last 90 days</li><li>Matches Query 4 (outreach list)</li></ul>| Major |
| OLAP-4 |As an Agency Manager I want to be able to view and print reports so that I can see consolidated information and keep a physical copy at hand if I do not have access to my computer.|<ul><li>Report contains information Agency requests<ul><li>Select items to generate report</li><li>make item hierarchy aka which report item should be on top and what comes next</li></ul></li><li>Able to generate a printable report<ul><li>Reports do not cut off at the edge of the page</li><li>Margins are respected</li></ul></li><li>Top-down report formulation</li></ul>| Minor |
