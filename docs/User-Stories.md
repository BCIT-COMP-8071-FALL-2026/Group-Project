# User Stories
## OLTP User Stories
| # | Epic | User Story | Acceptance Criteria| Priority |
|---|-------|---------|---------|---------|
| OLTP-1 |User Accounts and Login| As a Senior I want to be able to login so that I can information that pertains to me. | <ul><li>Successful login will show the home page</li><li>Failed login will show an "Invalid login attempt" error message</li><li>5 failed attempts lock the account for 5 minutes (ASP.NET Core Identity default)</li><li>A locked account shows the Lockout page, even with the correct password</li><li>A successful login resets the failed attempt count</li></ul>| Major |
| OLTP-2 ||As a Senior I want to be able to easily set up a secure account so that I can keep of my personal information.|<ul><li>Password is hashed by ASP.NET Core Identity and never stored in plain text</li><li>Password follows the ASP.NET Core Identity default rules (6+ characters, uppercase, lowercase, digit, symbol)</li><li>No email confirmation step is required to log in</li><li>Form contains boxes for:<ul><li>First Name (R) </li><li>Middle Name (O)</li><li>Last Name (R)</li><li>Email Address (R)</li><li>Phone number (R)</li><li>Address (R) <ul><li>Street, City, Province, Country and Postal Code are separate boxes, all required</li></ul></li></ul></li><li>Required fields are checked for presence only, no format validation, except Email Address, which must be a valid email format (ASP.NET Core Identity)</li><li>Selection option for Senior, Family or Staff</li><li>If Senior is selected: Birthday (R) and Living alone (yes/no) (R)</li><li>Senior gets the Senior role; Family gets the Family Member role</li><li>Staff accounts have no role and no access until Admin assigns one (OLTP-4)</li><li>Staff sees the home page with "Waiting for Admin to assign a role" and no role pages</li> </ul>| Major |
| OLTP-3 ||As a Senior I want my sessions to be secure so that I can have safe of mind that my data is protected.|<ul><li>Cookie sessions implemented</li><li>Session expires after 30 minutes of inactivity</li><li>Logout ends the session</li></ul>| Major |
| OLTP-4 |User Roles and Permissions | As the admin, I want to be able to turn accounts into Agency Managers or Caregivers and link them to an agency so that they can access their work pages. |<ul><li>Admin selects a user, a role (Agency Manager or Caregiver) and an agency</li><li>Agency is required when the role is Agency Manager or Caregiver</li><li>Saving replaces the user's existing role and links the user to the chosen agency</li><li>For a Family user, Admin selects a senior to link instead of an agency (OLTP-11)</li><li>Admin can change an existing user's agency from the same page</li><li>The new role takes effect on the user's next login, or within 30 minutes for an open session</li><li>Admin user list links each Senior to their profile, for editing (OLTP-8) and deactivation (OLTP-9)</li><li>Only Admin can access the page</li></ul>| Major |
| OLTP-5 ||As an admin, I want a clear hierarchy of roles and permissions so that I can ensure proper access to all users.|<ul><li>All roles are defined</li><li>All permissions are defined for each role in docs/Roles-and-Permissions.md</li><li>Permissions following least privilege only philosophy<ul><li>Only give each role what that role requires to work. Otherwise do not give them that permission.</li></ul></li><li>Roles include Senior, Family Member, Caregiver, Admin and Agency Manager</li><li>The Admin account is created by the seed script</li></ul>| Major |
| |Senior Profile Management||| |
| OLTP-6 |Create|As a Senior I want to input my personal data so that it can be used for future appointments and treatments|<ul><li>Form information<ul><li>Current Doctor name and phone (O)</li><li>Medical Conditions (O)</li><li>Current Medication (O, one text box)</li><li>Emergency Contact (O, OLTP-10)</li></ul></li></ul>| Major |
| OLTP-7 |Read|As a Senior I want to see all my personal data so that I can keep track of it.|<ul><li>Profile page shows all fields from OLTP-2 (except password and the Senior/Family/Staff choice) and OLTP-6, read-only</li></ul>| Major |
| OLTP-8 |Update |As a Senior I want to update personal information so that it is up to date.|<ul><li>Edit form shows the OLTP-7 fields</li><li>For the Senior, First Name, Middle Name, Last Name, Birthday and Email Address are greyed out and cannot be updated</li><li>All other fields can be updated by the Senior</li><li>Admin can update the greyed out fields, including the login email</li><li>Admin cannot change an email to one already used by another account</li></ul>| Major |
| OLTP-9 |Delete|As an Admin I want to be able to deactivate a senior's account if it is no longer needed so that it no longer appears in active lists.| <ul><li>Deactivate button on the senior's profile, available to Admin only</li><li>Deactivating sets the senior's Status to Deactivated immediately</li><li>Deactivated seniors are hidden from the OLTP-16 and OLTP-4 senior dropdowns</li><li>Admin user list still shows them, marked Deactivated</li><li>Deactivating sets the senior's future Scheduled visits to Cancelled</li><li>A deactivated senior cannot log in (ASP.NET Core Identity lockout)</li><li>Senior data is not deleted</li></ul>| Major |
| OLTP-10 |Family and Emergency Contact Assignment|As a Senior I want to record an emergency contact so that someone can be reached during emergencies.|<ul><li>The profile form has an Emergency Contact section: name, phone, relationship</li><li>Emergency contact is optional</li><li>The contact is shown on the profile (OLTP-7) and can be updated (OLTP-8)</li><li>One emergency contact per senior</li></ul>| Major |
| OLTP-11 ||As a family member I want to check on my grandparent/parent health and notes from caretakers so I can make sure they’re okay and follow any instructions that have been left.|<ul><li>Family member creates separate login</li><li>Admin links the family member to a senior from the admin page (OLTP-4)</li><li>Only able to access linked senior information</li><li>Same home page as a normal account, with an added read-only tab for the linked senior: profile, medical conditions, medication and caregiver notes (OLTP-15)</li></ul>| Major |
| OLTP-12 |Caregiver Assignment|As a caregiver I want to see all the visits I have been scheduled for so that I can manage my time and make it to each appointment.|<ul><li>Lists the caregiver's visits that are not Completed or Cancelled, in order of appointment times</li><li>Table format<ul><li>Time</li><li>Patient Name</li><li>Appointment Type</li><li>Resident address</li><li>Destination address (if applicable)</li></ul></li><li>The visit page (OLTP-14) shows all notes for that senior, newest first (OLTP-15)</li></ul>| Major |
| OLTP-13 ||As an Agency Manager I want to be able to assign qualifying caretakers to my patients so that I can ensure their needs are met.|<ul><li>List of patients displayed</li><li>Searchable by patient name</li><li>Drop down for eligible caretakers<ul><li>Eligibility:<ul><li>Trained</li><li>Time availability</li></ul></li><li>May cull caretakers list in the backend and only display eligible caretakers in the frontend</li><li>Each caretaker shows the agency they belong to</li></ul></li><li>Separate list for patients who do not have assigned caregivers for admin to work through.</li></ul>| Backlog (folded into OLTP-16) |
| OLTP-14 |Visit Logging and History|As a caregiver I want to be able to check-in and out when I reach my patient’s location and after I’m done so that my boss knows when I started and finished.|<ul><li>In the visit list (OLTP-12) user is able to select the visit in question to enter another page where they can log their activity</li><li>Check in button, check-out button</li><li>Logs the time of arrival and time of checkout and this is registered in the database as well</li><li>Check-in sets Status = InProgress; check-out sets Status = Completed</li><li>Check-in is available only when Status = Scheduled</li><li>Check-out is available only when Status = InProgress</li><li>Visit record stores ScheduledStart, ActualCheckIn, ActualCheckOut and Status</li></ul>| Major |
| OLTP-15 ||As a caregiver I want to be able to leave notes under my patients account so that future caretakers know what to expect or what to do better.|<ul><li>In the visit list (OLTP-12) user is able to select the visit in question to enter the page where they can log their activity</li><li>Text box on the same page as the check-in/check-out, with a button to save</li><li>Notes are saved against the visit and shown for the senior across all of their visits, newest first</li><li>Notes cannot be edited or deleted</li></ul>| Major |
| OLTP-16 (Added) |Visit Scheduling|As an Agency Manager I want to schedule a visit for a senior with a caregiver from my agency so that the visit appears on the caregiver's list and can be tracked.|<ul><li>Only an Agency Manager can access the scheduling page</li><li>Agency Manager selects senior, caregiver, date/time and visit type: Doctor, Home visit or Bathing (seeded)</li><li>Senior dropdown lists all active seniors</li><li>Caregiver dropdown lists only caregivers of the manager's own agency</li><li>The server rejects a caregiver who is not in the manager's agency</li><li>Agency Manager can enter an optional destination address (e.g. for doctor visits)</li><li>No separate caregiver assignment step is required (OLTP-13 is in the backlog)</li><li>ScheduledStart must be in the future</li><li>Double-booking a caregiver is not checked</li><li>Saved visit has ScheduledStart set, Status = Scheduled and AgencyID = the manager's agency</li><li>Scheduled visit appears in the caregiver's assigned list (OLTP-12)</li></ul>| Major |
| OLTP-17 (Added) |Missed Visit Detection|As an Agency Manager I want missed visits to be marked automatically so that reliability reports are accurate without manual entry.|<ul><li>Visit with no check-in within 60 minutes of ScheduledStart is shown as Missed, once ScheduledStart + 60 minutes has passed (60 minutes counts as within)</li><li>Cancelled visits (from seed data or OLTP-9 deactivation) are never shown as Missed</li><li>Shown status is Missed when computed as Missed, otherwise the stored Status</li><li>Missed is computed from the visit times, with no manual step</li></ul>| Major |
| OLTP-18 (Added) |Agency and Agency Manager|As an admin I want caregivers linked to an agency, and an Agency Manager role, so that managers can see their own agency's visits.|<ul><li>Agencies are created by the seed script, each with one Agency Manager and one Caregiver account</li><li>Each caregiver belongs to exactly one agency</li><li>In the OLTP app, an Agency Manager views and schedules (OLTP-16) only visits of their own agency, by the visit's agency at scheduling (Visit.AgencyID)</li><li>Agency Manager has a visits page listing their agency's visits, newest first: date, senior, caregiver and status (including Missed)</li><li>Admin can assign or change a caregiver's agency (OLTP-4)</li></ul>| Major |

## OLAP User Stories
| # | User Story | Acceptance Criteria| Priority |
|---|-----------|--------------------|---------|
| OLAP-1 |As an Agency Manager I want to be able to see the trend of scheduled visits and success or failure rates so I can accurately check on the reliability of services.|<ul><li>Line chart</li><li>Month as the x-axis and number of visits as the y-axis, across all agencies</li><li>2 lines, one is success and one is failure</li><li>Failure = Missed visit; Missed % = MissedCount / VisitCount, cancelled and not yet due visits excluded (Query 1)</li><li>Success = VisitCount - MissedCount (cancelled and not yet due visits excluded)</li></ul>| Major |
| OLAP-2 |As an Agency Manager I want to be able to check caregiver late clock ins so that I can fix the issue and ensure our patients are getting the care they need.|<ul><li>Bar chart</li><li>x axis are caregiver names, y axis is average minutes late</li><li>A visit is late if check-in is more than 10 minutes after scheduled start and it is not Missed</li><li>One bar per caregiver (Query 3, without agency or time of day grouping)</li><li>Average minutes late is over that caregiver's Late visits only</li><li>Caregivers with no Late visits are not shown</li><li>Average minutes late is rounded to 1 decimal place</li></ul>| Major |
| OLAP-3 |As an Agency Manager I want to know how many seniors are missing appointments so that I can follow up with them and ensure they are getting the appropriate help required.|<ul><li>Table</li><li>Name, Appointments missed, appointment types [as a list in a single column]</li><li>Also shows Lives alone (yes/no) and Age band (Under 65, 65-74, 75-84, 85+, at the anchor date) (Query 2)</li><li>Shows seniors with 3 or more missed visits in the 90 days before the anchor date (latest past, non-cancelled visit; both ends included)</li><li>Matches Query 4 (outreach list)</li></ul>| Major |
| OLAP-4 |As an Agency Manager I want to be able to view and print reports so that I can see consolidated information and keep a physical copy at hand if I do not have access to my computer.|<ul><li>Print button on the chart and table page</li><li>Printed from Chrome on Letter portrait, the chart and table fit within the page with nothing cut off</li><li>Table rows are not split across pages</li><li>Navigation is hidden when printed</li></ul>| Major |
